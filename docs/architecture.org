** Design decisions (recorded, Auto-RAGE)
1. *Prolog-authoritative KB.* SWI-Prolog modules under ontology/ hold the
   world model; a tagged-rule meta-interpreter (kb_rule/3 + explain/2)
   produces proof graphs. Rejected: vector-DB primary store (opaque, no
   symbolic proof); SQL primary store (no inference).
2. *Epistemic lattice.* observation/claim/proposal/fact/inference/hypothesis/
   rejected are distinct statuses in a single knowledge registry
   (register_knowledge/3). Rejected: separate predicates per status
   (no uniform provenance).
3. *Declared rules are knowledge.* Derived relations agents rely on
   (time_spent/3, port_owner/2, owning_package/2, ...) are declared with
   declare_rule/3 and provable via explain/2 with rule attribution.
4. *Governance as Prolog.* council_role/1, approval_threshold/2,
   quorum_met/1, promotable/1, shadow evaluation, promote/1 — the five-agent
   council (4/5 additive, 5/5 breaking) is executable policy.
5. *Module discipline.* Rules execute in their declaring module; explain/2
   is meta_predicate/0 on the goal so callers query from any module;
   leaf nodes record the defining module.

** Adversarial review findings (fixed before realize)
- Module-context loss in explain/2 (goal resolution failed from foreign

- use_module(ModuleName) does not resolve loaded modules in SWI 10 — rule

- Integer/float unification traps in interval durations (parse_time returns

- promote/1 could mark proposals blocked as a side effect during voting —
  removed; state changes only on real transitions.
- changed_together/2 had a duplicated subgoal; commit_affects/2 had a wrong
  definitional restriction — fixed.

** Design decisions (recorded, Auto-RAGE)
1. *Window+AFK only.* Editor/web buckets are skipped for now (no clean
   app/title mapping); a later slice can project them onto
   =project_activity/4=. Rejected: shoehorning web tabs into app sessions.
2. *Titles never enter the ontology.* Collector redacts (tokens >30 chars
   → =<redacted>=, truncate 80) and only the JSONL carries titles; ingest
   asserts no =window_title_i/2=. Rejected: trusting downstream redaction.
3. *Event identity = knowledge identity.* Knowledge item
   =aw_event(Bucket, EventId)= doubles as the =usage_source(…, activitywatch)=
   usage id, so dedup (=seen_event/1=), provenance, and
   =app_of_usage/activity_source= all key on the same term.
4. *Incremental at the collector.* State file stores last event id per
   bucket; JSONL is a per-run batch consumed by the same =make= invocation.
5. *Stdlib-only collector, ontology-only ingest.* =urllib= + =json=;
   ingest asserts only existing dynamic predicates plus provenance edges.

** Adversarial review findings (fixed before realize)

  file on a duplicate line — dedup skip is now an explicit success branch.
- =Kind = Event.kind= bound a JSON *string* against =window/afk= atoms and
  silently failed every event — all JSON strings are atomized on entry.
- =format_time(..., posix)= produced local-time ends (UTC−4 host) —
  replaced with =stamp_date_time(_, _, 0)= + =format_time/3=.
- JSONL EOF raised =unexpected_end_of_file= instead of =end_of_file= —
  reader catches exactly that term as clean EOF; malformed mid-file JSON

* Iteration 3 — Prolog-RLM harness, symbolic MoE, file mining (Auto-RAGE)

** Run identity
- Branch :: main (after merge of rage/2-activitywatch at b910e41)
- Date :: 2026-09-19

** Decision record
1. *Registry backend.* The real Prolog-RLM lives at
   ~/Documents/Projects/prolog-rlm (canonical main 51d2530). Its
   rlm_expert.pl expert registry exists only on the unmerged
   codex-symbolic-experts branch. Decision: rlm/harness/symbolic_rlm.pl is a
   facade that dispatches registry calls to upstream rlm_expert when
   SYMBOLIC_PROLOG_RLM points at a checkout containing it, otherwise to a
   bundled compat registry implementing the same published contract
   (expert_contract{id,version,goal:Op/Arity,priority,requires,handler},
   Handler(+Goal,+Context,-Value)). Same predicate names either way; no
   Symbolic code changes when upstream merges.
2. *Symbolic MoE.* Mixture-of-experts implemented purely symbolically in
   Prolog (rlm/experts/symbolic_moe.pl): experts carry keyword sets, the
   router scores priority + keyword overlap over the goal term, tries
   experts in rank order with fall-through on failure, records every
   selection as a provenance-tracked inference, and moe_council/5 asks the
   top-K experts and unions their answers.
3. *Tools as experts.* kb_query, kb_explain, kb_related, kb_assert_candidate,
   kb_search_code, kb_search_docs, kb_git_history, kb_services,
   kb_sessions, kb_debug_ctx, brave (bx context), web_fetch,
   wikipedia (REST summary + search) are registered experts with keyword
   sets; any Prolog-RLM or MCP client can invoke them through the registry.
4. *File mining.* rlm/mining/file_mine.pl walks a repository (depth-bounded,
   skipping VCS/build dirs), fingerprints files with sha1 for incremental
   re-mining, and extracts language/source_code/documentation facts with
   per-language line handlers (prolog module/use_module, python def/class/
   import, elisp defun/defvar/defcustom/defmacro, lisp defun/defpackage,
   js/ts function/class/import, rust fn/struct/trait, go func/type, nix
   options, org/markdown headings). Facts carry the content hash.
5. *Debugger expert.* prolog/experts/debug_rules.pl declares candidate_cause
   rules (broken service, package changed this week owning the subject path,
   prior failed session about the subject, documentation gap); the
   software_debugger expert returns candidates WITH rendered proof graphs,
   so causes stay hypotheses with evidence, never assertions.

** Adversarial findings fixed during realize
- use_module(ModuleName) does not resolve loaded modules (recurring); all
  cross-module imports now use relative file paths.
- depends_on/2 exported by both provenance and source_code -> renamed the
  source_code one to project_depends_on/2.
- 0'X char-code integers never equal atom_chars atoms -> balance Strip
  compared '(' as atom; balance must strip at the head of the reversed
  list (append-tail variant can never match).
- call(Goal, Arg) appends an argument: inline disjunction handlers got
  arity errors silently; replaced with per-language handler closures.
- add_defines fails on known symbols, poisoning the scan line; scan loop
  now ignores handler failures per line.
- compat registry create must accept caller-supplied registry names.
